# 模型工作区技术设计

基线：ClipSlots v2.17.97。需求正文位于同目录 `index.html`，本文件只定义工程接入与验证。

## 接入点

- `WorkspaceModeSwitcher.swift` 当前 `.agent` 是标题为“模型”的禁用占位。保留旧 raw value 兼容，开放该项；中心计算须支持第三项，不能沿用所有非画布项都落在编辑位置的算法。
- `ContentView.requestWorkspace` 与独立工作区分支挂接新的 `ModelWorkspaceView`，由独立状态容器持有数据。模型页面不订阅画布指针和逐 token 的 Agent 状态；已有顶部导航的均匀柔和边框和连续动画保留。
- 现有生成来源为 `GenerationProviderID.crate/byteartist`；任务绑定 `GenerationProviderContext`，提交未知禁止自动重提。新测评执行器必须复用这一契约。
- `AgentConfig` 已支持完整 chat/completions 地址、模型标识与显式图像输入能力；统一目录经桥接提供 Agent 选择，凭据采用现有 Keychain 路径与新增服务键，不能进入可导出元数据。
- 现有槽位为 page → group → numbered slot，每组容量受当前配置约束。GUI 题库写入必须经 `SlotStoreObservable`；测评快照读取权威存储，渲染缓存不能作为存在性或覆盖许可。

## 工程模块

1. Kit 层增加模型服务 / 模型配置、用途绑定、题库索引、题目及结果集、六维评分与适用性模型，版本化持久化到独立目录。写入使用原子替换并在修改冲突时拒绝覆盖；读失败保留 unknown/error，禁止把损坏文件当空库写回。
2. 配置中心提供 HTTP API 合集与内部 CLI 合集。HTTP 包含 OpenAI 兼容 LLM / 图像接口及可配置异步媒体任务契约；CLI 复用 Crate、ByteArtist、Tika 的发现、登录与提交接口。能力不明确时禁用对应运行并显示原因，不猜测响应路径。
3. 测评执行器固定模型和题库快照，为每个题目 × 模型生成独立单元，最多 14 个模型。调度器按设置及 `ResourceBudget` 限制在途请求；支持取消、单元重试、已确认远端任务恢复与提交未知保护。
4. 题库桥接绑定页面 / 组 / 槽位，保存文本、附件版本与索引映射。出题使用指定 LLM 的无工具结构化响应，草稿校验后经用户确认写入槽位；写回占用槽位走现有冲突路径。
5. 排行榜基于真实结果和显式评分。无评分不生成分数或排名，适用性和评分口径构成分组键。六维图显示缺失状态；结果预览复用缩略图预算与原始媒体比例。
6. 新闻服务使用 URLSession 与 RSS / Atom 解析，来源配置、去重、原文发布时间、抓取时间和离线缓存分离。仅抓取公开源，不调用真实生成测试；页面进入才检查每日刷新，后台无持续轮询。

## 兼容与验证

保留当前槽位、附件、画布和 Agent 原配置；旧配置导入统一目录可重复执行且不能重置已有选择。默认用途绑定对未完成任务不产生影响。内部 CLI 配置不是新的隐式后备源。

验证采用隔离数据目录、假凭据与本地 HTTP / CLI fixture。覆盖 14 / 15 模型边界、题库双向同步冲突、素材版本变化、输入快照、异步成功 / 失败 / 未知提交、取消与单元重试、评分缺失 / 不适用、RSS / Atom 无日期及离线恢复、密钥脱敏和遗留配置兼容。不得发起真实付费测评或出题。

正式交付按现有 guarded release：三个产品构建、签名、候选隔离启动、业务数据与偏好完整备份、安装后严格字节核验，再提交、推送和发布。此前导航检查中“模型未开放”的预期须更新为实际可进入模型工作区；不能保留旧检查却宣称通过。
