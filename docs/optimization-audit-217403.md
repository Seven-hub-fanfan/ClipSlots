# ClipSlots 2.17.4（217403）优化排查

建议先处理生成入参、保存失败反馈和附件撤销，再处理预览、任务状态及 Agent 会话体验。当前主流程命中测试通过，不代表异常数据、外部文件变化、任务中断等组合已被覆盖。

**1. 生成入参校验应放在提交之前。**

触发方式：上游 IMAGE 还未生成或正在重跑，下游 IMAGE 已有提示词，此时点击下游生成。`startGeneration` 只在提示词为空时使用 `pendingUpstreamCount` 提示上游未完成；提示词非空就继续执行。

探针得到 `pendingCount=1`，生成参数构造成功，但 `--image` 数量为 0。此处验证到参数层，没有向真实生成服务提交，因此不把它描述成实测已扣费。

另外，上游 VIDEO 成功产出的 `.mp4` 可沿自动连线进入下游 IMAGE 的 `--image`。应根据输入端能力判断能否连接；视频引用图片生成需要明确抽帧，或给出“不支持此输入类型”的提示。不能把原视频文件当图片交给 CLI。

建议：生成前汇总“缺失、等待、不可用、类型不兼容”状态；多选关联节点生成时按依赖顺序执行；正常可用的入参直接提交，无需增加多余确认步骤。

位置：`CanvasWorkspaceView+Generation.swift:6–25,28–87,169–182`，`CanvasEdgeInputs.swift:38–42`，`CrateGeneration.swift:225–245`。

**2. 画布需要可见的保存状态和失败重试。**

探针将临时存储根设置成普通文件，制造目录创建失败。结果为 `saveReturned=false`，但内存缓存仍有 1 个节点；清除缓存后重载得到 0 个节点。

`CanvasStorage.save` 在磁盘写入成功之前更新缓存；`CanvasStore.scheduleSave/flushSave` 不处理返回的失败值。实际遇到路径、权限或磁盘异常时，用户可能认为修改已保存。

建议：保留待保存快照；展示“保存中 / 已保存 / 保存失败”；失败可重试。切项目或退出时对实际未保存的数据给出明确反馈。这里没有发现用户真实数据已经丢失，问题来自本轮临时目录故障注入。

位置：`CanvasStorage.swift:107–131`，`CanvasStore.swift:1093–1127`。

**3. 附件增删和排序需要共用一套撤销事务。**

扇形卡片的新增、置顶、删除会调用 `canvas.recordSlotAttachmentEdit`，删除还会暂存附件字节。入参面板的 `writeAttachments` 直接写槽位存储，没有接入这条画布历史。

对画布私有槽位，底层直接写存储；对当前正式组，使用编辑侧的撤销机制。两者都不等同于画布的附件撤销栈。用户在面板中删图后按画布撤销，可能撤销的是之前的移动或连线。

建议：统一新增、删除、排序、置顶的事务入口；一次拖动排序只记一条历史；写入失败不推进历史。这项已确认调用路径差异，尚未新增原生面板删除与 ⌘Z 复现。

位置：`AttachmentManagerPopover.swift:111–117,565–601`，`CanvasWorkspaceView.swift:1459–1540`，`main.swift:2803–2843`。

**4. 图片“能入参但看不到”和“换图后还显示旧图”均可复现。**

- 同一有效 PNG，使用 `.image + storagePath` 有缩略图；使用 `.file + storagePath`、没有 `path` 时缩略图为 nil，而生成筛选能识别出 1 张图片。附件预览的 `.file` 分支只读取 `path`。
- 将同一路径的横图覆盖成竖图，附件 ID 不变。再次请求缓存仍得到 `80×40`，直接重新解码为 `40×80`。画布缓存键只有附件 ID 和目标尺寸，缺少文件修改时间/大小；视图也只监听附件 ID。

建议：统一附件解析，优先使用可靠的存储路径并提供回退；缓存键包含文件版本，支持外部原图变化和失败后的恢复。避免用户通过重启应用来刷新预览。

位置：`AttachmentManagerPopover.swift:838–884`，`CanvasNodeAttachments.swift:28–30,65–78,198–215`。

**5. “参考图数量”应显示模型实际使用的图片。**

使用七图槽位连接 VIDEO。对于 `framesExcludeReferences=true` 的模型，自动连线分配第一图为首帧，其余为参考；模型规则正确排除互斥参考后，实际只剩首帧 1 张。输入区则按通用图片引用规则显示 7 张。

这不是要求强行给不支持的模型传七图，而是需要让用户看见“首帧 1 张，另 6 张本模型不使用”，并能调整首尾帧、参考图角色。目录未加载时当前视频路径还会只取首图，丢弃尾帧和参考图，生成前也需要说明。

位置：`CanvasNodeComposer.swift:120–124`，`CanvasWorkspaceView+Generation.swift:51–69`，`CanvasEdgeInputs.videoFrames`。

**6. 已提交任务应优先恢复，避免误重跑。**

探针确认 `.running + taskId` 经保存和重载后变为 `.idle + taskId`。这是避免永久显示“生成中”的合理处理，但 UI 没有独立的“待恢复任务”状态。

当前“取回结果”能继续查询旧任务；普通生成仍会进入 `beginGeneration(recovering:false)`，清掉旧 taskId 并发起新提交。建议重启后自动查询未完成任务，或把主要按钮改为“继续查询”；保留单独的“重新生成”。取消也应明确区分停止本地跟踪与取消远端任务，取决于服务端能力。

位置：`CanvasModels.swift:126–154`，`CanvasStore.swift:443–452`，`CanvasNodeComposer.swift:144`，`CanvasWorkspaceView+Generation.swift:91–141`。

**7. Agent 停止工具时需要同步结束工具行。**

模拟模型发起 `list_slots`，工具执行期间调用 `stop()`。结果：`isRunning=false`，但 transcript 工具状态仍为 `running`，没有对应的 tool 结果。

原因：停止后作废了后续回调，未完成工具的消息状态没有补成“已停止”；transcript 将缺少结果的工具统一视作运行中。建议补齐取消终态，保留执行结果是否已知的区别；继续对话前确保工具调用与结果配对完整。

位置：`AgentChatModel.swift:217–225,288–305,346–357`。

**8. Agent 会话应能够保留并找回。**

模型探针中，已有 2 条消息和未发送草稿，执行新建后变为 0 条消息、空草稿。当前 `AgentSessionStore` 只持有编辑/画布各一个内存对象，没有历史会话存储。

建议：新建时归档旧会话，提供最近会话入口，并持久化草稿；支持把当前槽位或选中节点作为清楚可见的对话上下文。后者属于产品增强，不能声称当前 Agent 已理解画布选中内容。

位置：`AgentSidebarView.swift:97–151`，`AgentChatModel.swift:228–239,379–389`。

**9. 性能优化应先盯视频元信息和缓存容量。**

独立微基准：100 个不同附件 ID 指向同一条短视频，在主线程连续调用真实 `CanvasMediaProbe.facts`，首轮约 **85.9ms**，第二轮约 **66.7ms**。缓存上限为 96，超限整批清空，第二轮仍不断重新探测。同步路径包含时长和视频轨道读取。

这是元信息函数耗时，不是整套应用的帧率测试，也不能外推为所有用户都会卡这么久。建议改为有界 LRU/成本缓存和后台预取，按附件变化更新；在 100/300 节点场景下分别采样首次进入、滚动、缩放和内容变更的主线程耗时。

上一轮回归日志中的多次约 1.3 秒停顿紧邻 `snapshotWindow`，受测试截图影响；本报告没有把这些数值当作日常交互卡顿证据。主画布平移的节点内容求值增量为 0，已有隔离优化应保留。

位置：`CanvasMediaProbe.swift:81–114,161–171`，`CanvasMediaLayout.swift:7–15`。

**10. 清理容易造成“功能失效”印象的入口与提示。**

- 添加菜单的音频、3D、剪辑时间线、3D 片场均为不可用项，只在悬停说明“暂未接入”。建议收进“即将支持”区或持续展示状态，减少用户误判为点击失效。
- 文本节点菜单仍写“脚本、广告词、品牌文案”，实际按钮行为是生图 Prompt 优化，需统一说明。
- 默认 Agent 系统提示仍自报 `v2.11.8`；应动态注入当前版本。
- 生成错误在节点上只显示两行，建议可展开完整原因，提供复制诊断信息及对应操作。

位置：`CanvasAddNodeMenu.swift:55–60,94–102,172–174`，`AgentService.swift:190–199`，`CanvasTapNodeCard.swift:391–405`。

推荐实施顺序：第一批修生成校验、保存反馈、附件撤销及预览；第二批修任务恢复、实际入参说明、Agent 状态和会话；第三批做大画布性能与入口文字打磨。每批用针对性异常场景验证，保留已经通过的真实鼠标命中回归。
