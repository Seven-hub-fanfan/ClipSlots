# 素材节点与生成节点的上传行为修复

## 用户可见变化

- 空白处双击菜单创建的图片/视频是**素材节点**：单击卡内上传直接选择一份同类型文件；再次上传为替换，卡片显示素材及其真实比例、尺寸，视频支持播放预览。
- 从图片/视频/文本等上游拖线创建的图片/视频是**生成节点**：提示词面板的“＋”直开文件选择器，可多选；上传内容显示为入参缩略图，主预览只显示生成结果。
- 素材不显示生成面板，也不会被批量生成误提交。生成节点的入参管理、删除、排序及独立预览入口保留。
- 素材替换后下游自动引用新文件；撤销/重做恢复原文件、身份与比例。
- 粘贴多个本地图片/视频会分别创建素材节点，每个节点一个文件。
- 节点用途持久化，断线、移动、入库和重启不会改变用途。

## 原因与实现

217802只增加了显式入参身份，误将独立素材也当作生成节点处理。菜单虽然区分“图片”与“生成图片”，创建路径却没有保存用途；同时，下游只读取succeeded状态中的路径，无法引用普通上传素材。

`CanvasNode.mediaRole`保存source/generation，创建入口依据完整父节点数组赋值。旧文档结合连线、任务与明确产物迁移，仅迁移缺少角色的节点，不删除历史附件。217802曾误标input的素材仍可正常预览。

上传入口按角色限制数量与类型，回调复核项目/节点身份，取消或拒绝不写入。素材替换与生成入参编辑共用附件stash及undo事务。`CanvasMediaPick.primary`统一主卡片、比例、全屏与下游引用；生成输入不会被当成输出透传。真实模型支持的输入类型仍沿用既有能力规则。
