# 搜索增量更新与完整结果合同

适用：V2.17.104，M09/M10进行中。业务文件是权威来源，SQLite及内存对象均为可重建缓存。

## 一致性边界

- 每次完整查询必须检查捕获范围内的文件版本；查询本身不是跨所有分组的业务事务。
- 文件事件和成功业务写入revision只提示受影响的槽位，不授权覆盖、删除或归档业务内容。
- 不能把事件同步刷新视为全部磁盘变更已送达。2026-10-30本机100次连续原地写入实验，立即刷新后有68次未收到目标文件事件，原始实验单列保存。
- 更新只解码变化槽位并在SQLite事务中替换相应行与版本；未变化行保持原字节。槽位数变化、缓存结构损坏、事件丢失或范围不明时允许可取消重建。
- 读取前后必须核对文件描述符和路径身份；取消、短读、权限错误、非普通文件及预算超限不得缓存为“确实为空”。
- 搜索保留完整正文、中文、Unicode规范等价、NUL与短子串语义。GUI附加槽号，CLI内容检索不附加槽号。

## 展示与操作边界

- 首屏、已累计数量、全部完成独立状态。未完成时不得显示“全局未找到”或宣称最终数量。
- 同一查询的页必须按同一严格排序键产生；相同名称/顺序使用page/group/slot身份消除并列不确定性。
- 查询/筛选/范围/排序/活动上下文改变时取消旧任务并立即换generation；迟到页不得写入新查询。
- 完整结果保留在后台查询状态；挂载的行按页增量增加，不以已挂载页限制完整结果操作。
- 全选、复制、导出若存在，只能对已完成的完整结果快照执行；不能静默只操作首屏。

## 验证口径

引擎基准、原生输入框（含200ms去抖）、首屏呈现、完整结果、首次索引分别记录。DEBUG诊断与Release计时不混算。历史测试不能代替当前源码，32GiB本机不替代实体低内存矩阵。
