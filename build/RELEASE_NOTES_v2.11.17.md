## ClipSlots v2.11.17

### 画布图像节点接入 Crate CLI 真实生图

画布上的图像节点从"占位"变成真出图：走本机已登录的 `crate` CLI，提交 → 轮询 → 下载 → **产物写回槽位附件**。

- **提示词取槽位正文，入参图取槽位附件**：节点自己不存正文、不存文件，只记 `taskId` / `seed` / `state`。画布是派生资产，用户资产始终在槽位里，删画布不掉图。
- **产物落地为槽位附件**，节点里存的是附件的本地字节路径而不是 CDN URL（URL 会过期，而节点状态要落盘），卡片预览与槽位附件永远同一份字节。
- **重跑复用 seed**；模型不收 seed 时（如 seedream45）自动去掉并弹一句提示，不让人误以为"同样参数出了不同的图"。
- **GUI 下的 PATH 修正**：从登录 shell 取 PATH 并提前检查 node，避免 Finder 启动时 `crate` 找不到 node 只报一句看不懂的错。

### 修复：历史产物不再污染下一次生图的入参

产物现在有**两道独立标记**：节点上的 `outputAttachmentIds`（精确）+ 产物文件名 `crate_<taskId>.<ext>`（兜底）。

只靠前者不够——画布文档会被**不认识这个字段的版本**读写，Codable 遇到未知 key 直接丢掉，于是"用旧版本打开一次画布"就足以抹掉全部产物标记，下一次重跑立刻从文生图静默退化成图生图（实测发生过：一个槽位里三张历史出图全被当参考图上传）。文件名跟着字节走进槽位，不受文档往返影响。

判定刻意只认 `crate_` 前缀 + 图片扩展名这一种极窄形态，宁可漏判（还有 id 那道标记兜着）也不误判用户自己拖进来的图。另外生图取入参时落一条日志（图片附件数 → 入参数 → 跳过产物数），因为产物判错在 UI 上完全看不出来。
