## ClipSlots v2.10.87

先做了一轮性能盲点复扫，再针对切组/切页/搜索路径打磨动画过渡。

### 性能：三处「已被优化掩盖」的盲点

- **删除 write-only 的 `slotRenderTokens`**。它是 v2.10.72 之前「靠改卡片 `.id` 强刷缩略图」方案的遗留物；v2.10.73 把缩略图改成由 `ThumbnailProvider` 的 keyed 缓存驱动后，全仓再无任何读取点，却仍保留了 **16 处写入**。因为它是主 store 上的 `@Published`，每次写入都让 `objectWillChange` 发射、整棵 `ContentView.body`（标题栏 / 搜索区 / 含 10 张卡片的 LazyVGrid / 底栏）重新求值——为一个没人读的值付全局重绘的代价。最坏是撤销清空 / 清空全部 / 批量导入 / 批量保存里的 `for slot in 1...config.slots` 循环，一次操作连发 10 次。删除前逐一核验过全部 16 处：每处都伴随 `slots` / `refreshTrigger` / `reloadAllAsync()` 中至少一个，刷新链路由真实数据变更保证，时序与可见行为不变。
- **导入进度 `importProgress` 下沉到 `TransientUIStore`**。它是全仓更新最频繁的状态之一（每处理一个条目上报一次，几百个文件就是几百次），却挂在主 store 上，于是每次百分比前进都触发整棵 body 重算。卡片的 Equatable 能拦住像素重绘，但视图树 Diff 本身就吃满了导入期间的主线程，表现为「导入大批文件时界面发涩、hover / 滚动不跟手」。现由独立的 `ImportProgressOverlayView` 单独承接，进度推进只重绘那一条 340pt 浮层。视觉与非模态行为完全不变。
- **全局搜索 `resultsSignature` 零分配化**。原为 `results.map(\.id)`，是计算属性，因此**每次** body 求值都新建一个 N 元数组 + N 次字符串引用计数——而 hover 某一行、切换选中项、改排序都会走一遍。命中几百条时正好在「输入搜索词」这个最需要跟手的路径上每帧几百次无谓分配。改为把全部 id 折进一个 `Hasher` 得到 `Int`，语义等价、零堆分配。

> 复扫中另有两项曾被怀疑的热点经核验**已在早前版本解决**，本次未改动：槽位 `preview` / `plainText` 已有以 `contentId::updatedAt` 为键的 NSCache（非每次全量解码）；组内搜索匹配计数已在 v2.10.49 做了防抖 + `@State` 缓存。

### 动画：补掉硬切，修正读不到的过渡

- **缩略图「占位 → 出图」淡入**。异步解码完成的瞬间原先是「啪」地替换，跳变感明显；现在是 0.2s 显影。
  这里的动画是**有方向的**，刻意用 `isLoaded`（Bool）而非 `currentKey` 作驱动键，以免碰到「切组/切页立即刷新、不串图」这条被 v2.10.64/65/86 反复修过的不变量：图 A → 图 B（新 key 已命中缓存）时 Bool 不变、**仍是瞬时硬切**，不会出现两组的图交叠淡化；有图 → 占位（切到未缓存的组）时动画取 `nil`、旧图**立即**消失，不留淡出尾巴。只有「占位 → 有图」这一个方向拿到动画。
- **搜索结果区出现 / 消失过渡**。原为裸 `if isSearchActive { ... }`：敲下第一个字符时这一整块凭空出现、把槽位网格硬生生往下顶一大截，清空时又整块消失、网格「弹」回原位——搜索路径上观感最突兀的一处。现改为「淡入 + 自顶部展开」，`.animation` 紧贴该 Group 作用域，只由一个布尔驱动（逐字符输入不会反复触发），时长用 0.2s 压短，因为这一下会带动 10 张卡片所在容器的纵向布局。热键错误横幅同样补上，两处纵向插入节奏一致。
- **切组扫光真正可见**。原实现 0.95s 走完一趟且起点整条在画面外，而光带是「两端透明、中心最亮」的渐变，真正看得见要等中心入画（≈0.22s）；v2.10.74 之后遮罩只在切组确实慢时才延迟显示，实际窗口常只有两三百毫秒。两者一叠加，这道扫光在多数真实切组里几乎从没亮起来过，用户看到的只是「内容淡了一下又回来」，没有任何「正在加载」的交代。现行程压到 0.72s、起点改为半露，第一帧即可读。遮罩何时出现/消失仍完全由 `isSwitchingGroup` + v2.10.74 的延迟 token / 1.2s 兜底决定。
- **切组 0.16s 收进 token 体系**为 `Anim.groupSwitch`：数值与曲线一字未改，仅从魔法数变具名常量，并写明这一档为何刻意独立、不要调大。

### 未改动 / 遗留

- 卡片「展开」走的是系统 `.sheet`，无可定制的过渡空间，未强行介入。
- 游标胶囊位置、拖拽排序：均未触碰。
- 遗留技术债：`refreshTrigger` 同样是「23 处写、0 处读」的 `@Published`，但它是多条路径唯一的「强制刷新」副作用通道，删除风险高于收益，本次保留待专项梳理。
