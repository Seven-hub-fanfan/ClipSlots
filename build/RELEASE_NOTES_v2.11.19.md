## ClipSlots v2.11.19

### 画布能出视频了：7 个视频模型全部接上

v2.11.17 接上 Crate CLI 能真出图，v2.11.18 让模型和尺寸可选，但「视频节点」一直只是数据模型里的一个枚举值 —— ADD NODE 菜单里没有它，属性面板也没有它。这一版把它接通：**新建视频节点 → 选模型 / 比例 / 分辨率 / 时长 / 配音 → 点生成 → mp4 落进槽位附件、卡片上显示首帧**。

可选的 7 个模型全部来自 CLI 现问的目录（`crate model list --json`）：

| 模型 | 时长 | 分辨率 | 输入图 |
| --- | --- | --- | --- |
| Seedance 2.5 | 4–30s（可自动） | 480p / 720p | 可选，首尾帧 |
| Seedance 2 | 4–15s | 480p → 4k | 可选，首尾帧 |
| Seedance 2 Mini | 4–15s | 480p / 720p | 可选，首尾帧 + 参考图 |
| VEO 3.1 | 4 / 6 / 8s | 720p → 4K | **必填** |
| MiniMax H3 | 4–15s | 768P / 2K | 可选 |
| Seedance Pro 1.5 | 4–12s | 480p → 1080p | 可选，首尾帧 |
| Seedance Pro 1 | 2–12s | 480p → 1080p | 可选，首尾帧 |

### 为什么不是「把图像那套参数复制一遍」

视频与图像共用「提交 → 轮询 → 下载 → 写回槽位」的骨架，但有四处必须分开处理，每一处都是静默错误的温床：

- **参数必须按模型裁剪，而不是灰掉。** 传一个模型没声明的参数会被 CLI 当场拒收（实测给 `seedancePro1` 传 `generate_audio` 直接报 `does not publish parameter`），整次生成失败。所以「分辨率 / 时长 / 配音」三项是**模型声明了才出现**：一个永远点不动的开关只会让人反复怀疑自己哪里没配对。
- **时长有两种形态。** 6 个 Seedance/MiniMax 给的是 `min/max/step` 连续区间，`veo-3.1` 给的是离散枚举 `[4, 6, 8]`。用 min/max 去套 veo 会让 UI 允许选 5s、提交才被拒；用枚举去套 Seedance 会把 4~30 秒砍成几个档。换模型时旧值会被**夹到新模型的合法档位**（30s 换到 veo → 8s），而不是留着一个必然被拒的值。
- **输入图按角色分，而且有互斥约束。** 槽位里的图不是一把塞给 `--image`：第 1 张是首帧、第 2 张是尾帧、其余作参考图。更要命的是 **7 个模型里有 5 个声明了「首尾帧不能与参考图共存」**（实测 `--first-frame + --reference-image` 给 Seedance 2.5 → `First/last frames cannot be combined with multimodal references.`），所以互斥的模型只拿前两张、余下的丢掉，并在面板上写明「其余会被忽略」—— 用户挂了 5 张图只生效 2 张而不说一声，看起来就是个 bug。
- **产物是 mp4，预览要另走一条路。** 卡片预览区原本只有 `NSImage(contentsOfFile:)` 一条路径，它对 mp4 **静默返回 nil**：症状不是报错，而是「生成成功了但卡片一片空白」，与「生成失败」在视觉上完全一样。现在视频产物用 `AVAssetImageGenerator` 抽首帧，叠一个播放图标 + 时长角标；抽帧失败时显示「视频已生成」而不是失败态 —— 任务在服务端是成功的、额度已经扣了，显示成失败会让用户白白再跑一次。

### 其他要紧的细节

- **轮询时限从 600s 提到 1800s。** 图像那 600s 对视频是不够的：最便宜的 `seedance2-mini` 480p/4s 实测就要 ~80s，而 Seedance 2.5 允许 30s 时长、Seedance 2 允许 4k，排队高峰十几分钟是正常的。600s 超时的症状特别恶劣 —— 任务在服务端**已经成功并扣了额度**，App 这边报「超时失败」，用户只会再点一次。
- **VEO 的必填图在点生成时就拦住**，而不是提交后换一条英文报错回来。
- **参数降级与图像同构**：CLI 真拒收某个参数时去掉它重试一次，并 Toast 说明「本次用了模型默认值」，不静默改行为。降级只降参数、**不降输入图** —— 把用户挂的首帧丢掉等于换了一次生成语义。
- 首帧抽的是 `min(0.6s, 时长×10%)` 而不是第 0 帧：很多模型的第一帧是纯黑淡入，抽 0s 得到一张全黑图，看着和没预览一样。
- mp4 写进槽位时类型仍是 `.file`（附件 schema 不动，视频身份按扩展名判）—— 给历史 schema 加一个 `.video` 类型会让老版本读不了新数据。
- 缩略图缓存键带 mtime + size：同一槽位重跑生成产物路径可能一样，只认路径会一直显示上一条视频的首帧。
- 抽帧要带上轨道的旋转矩阵（`appliesPreferredTrackTransform`），否则 9:16 竖片的首帧会被画成横的。

### 附带修一个反复漂移的 CLI 版本号

`clipslots version` 报的是一个写死常量，它已经漂移了三次（2.10.16 → 2.10.58 → 2.11.8，而 App 已经到 2.11.18）。代码里从 v2.10.30 就写着「每次发布请与 App 版本保持一致」—— 靠注释提醒人手动同步的制度已经被证伪三次了，而盯它的那条 smoke 断言把期望值也写成了字面量，于是测试跟着实现一起错。

现在 CLI **从所在 app bundle 的 `Info.plist` 读版本号**（唯一官方安装路径就是 `/usr/local/bin/clipslots` → `ClipSlots.app/Contents/MacOS/clipslots-cli`，plist 就在上两层），与 GUI 的 `AppVersion.current` 同源；smoke 的期望值也改成现读 Info.plist。字面量只剩一个兑底值（`swift run` 直跑、没有 bundle 可问时用）。

- smoke **32046 项全通过**（新增 `CRATE-VID` 组 66 条：提交参数拼接 / 参数降级 / mp4 兜底扩展名 / 目录视频字段解析 / 两种时长规格的夹取 / 换模型落值 / 输入图角色分配含互斥）
