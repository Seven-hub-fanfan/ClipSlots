# ClipSlots v2.13.0 · 画布项目 + 暂存内容跟着节点一起消失

两件事，都是上个版本遗留的产品问题。

## 1. 「未入库」终于是暂存区，而不是垃圾堆

**问题**：v2.11.8 给画布节点安排了一个保留组「未入库」当停车场（画布上凭空新建的节点总得有个地方存内容）。但删节点时只删了节点、**没碰槽位内容**——于是画布上明明是空的，未入库里却堆着一地删过的节点残留，越用越脏。

**改法**：不是在「删除」这条路径上顺手清一下（那样和撤销打架——Cmd+Z 能把节点恢复回来，但内容已经被清掉了，恢复出一个空节点比残留严重得多），而是立一条**声明式的不变量**：

> 暂存区里只允许存在两种内容：① 当前画布上有节点引用的；② 撤销 / 重做栈还能恢复出来的。

其余的就是垃圾。这条规则对「删节点」「改绑槽位」「上个版本留下的脏数据」一视同仁，不需要为每条路径各写一遍清理逻辑。执行时机是两处：删节点之后、以及每次进画布时（后者顺手把历史残留一次清干净）。

**三层安全**，因为这个逻辑会动用户的内容：

- 规则判定全在 Kit 层纯函数里，带 42 条 smoke 断言；
- **画布文档读取失败时一个都不清**。文档损坏会回落成空画布，那时"没有任何节点引用"是假象，清扫会把整个项目的内容一次抹掉——这是唯一的灾难性失败模式，在入口就堵死了；
- 真正的清除走 `.trash` 软删除，**30 天内可恢复**，而且清完会提示你清了几条。

从槽位库拖上画布的节点不受影响：那是你的正式槽位，画布无权处置。

## 2. 新建项目

一条片子一张画布。左上角（紧挨侧栏）新增项目切换器：切换 / 新建 / 重命名 / 删除。

- 每个项目**各自一份画布文档**（节点、连线、视口都独立），互不干扰；
- 每个项目**各自一个暂存区**。之前 60 个槽位是全局共享的，三个项目各 25 个节点就撞墙；现在各占一个池子，而且删项目能把它的内容一起带走（同样进回收站）；
- 老用户的画布**自动迁移**成「默认项目」，暂存内容原地不动（默认项目认领原来的「未入库」，不搬家）；
- 项目索引坏了不会"丢弃重来"——那等于所有画布一起失踪。它会扫目录把孤儿项目捞回来。

切项目会先把当前项目落盘，并清掉撤销栈（跨项目 Cmd+Z 会把 A 的节点写进 B 的文档）。

## 安装

下载 DMG → 拖入「应用程序」。首次打开如提示未验证开发者，右键「打开」。
