# ClipSlots v2.10.88

主题：**动画提速 + hover 状态下切槽位卡顿修复**（两项均为 v2.10.87 引入/暴露的观感与性能问题）

## 1. 动画提速（v2.10.87 三处动画体感偏慢）

新增两档专用动画 token，替换原先笼统复用的 `Anim.status`（0.2s easeInOut）：

| 场景 | v2.10.87 | v2.10.88 |
|---|---|---|
| 缩略图「占位 → 出图」淡入 | `status` 0.2s easeInOut | `Anim.thumbnailFade` **0.09s easeOut** |
| 搜索结果区展开 / 收起 | `status` 0.2s easeInOut | `Anim.reveal` **0.13s easeOut** |
| 热键错误横幅展开 / 收起 | `status` 0.2s easeInOut | `Anim.reveal` **0.13s easeOut** |

- 缩略图是切组后第一眼要读的信息，淡入超过约 0.1s 就会被读成「图加载得慢」而不是「显影得好看」；改 easeOut 后透明度起手即快速拉起。
- 搜索结果区会带动整个槽位网格的纵向布局，属于大面积位移，感知时长天然更长，0.2s 在连续输入搜索词时明显拖节奏。
- **缩略图淡入的方向性逻辑一字未改**：驱动键仍是 `isThumbnailLoaded`（Bool）而非 `currentKey`，因此「图A→图B」仍是瞬时硬切、「有图→占位」仍立即消失，v2.10.64/65/86 的「切组立即刷新、不串图」不变量完好。

## 2. hover 展开状态下切换槽位卡顿（perf）

复现：鼠标悬停在某张槽位卡片（卡片放大、描边加深）时，移到另一张卡片，UI 明显发卡。

定位到 hover 路径上两处逐帧重算：

- **卡片阴影的模糊半径随 hover 变化**（radius 5→9、y 2→4），而链尾的 `.animation(Anim.interactive, value: isHovering)` 把它一并纳入隐式动画。高斯模糊半径变化无法靠图层缓存复用，只能整块重新合成——即 0.12s 内逐帧重新做一次卡片级模糊。鼠标从一张卡移到相邻卡时，**两张卡片同时各跑一遍**（离开的减半径、进入的加半径）。
  → 修复：阴影 radius / y **不再随 hover 变化**。hover 反馈完全由描边加深加粗（纯矢量、无模糊）+ 缩放承担，观感差异极小。
- **`scaleEffect` 直接作用在未拍平的多层子树上**（背景 + 阴影 + 描边 + 顶部胶囊 + 角标 + 缩略图 + 文本 + 按钮），缩放每一帧都要把各图层分别重新光栅化再合成，文本与图片还要按非整数缩放重采样。
  → 修复：缩放前插入 `.compositingGroup()`，先把整张卡片拍平成一层，缩放退化为对单个位图做一次 GPU 变换，成本与卡片内部复杂度解耦。视觉不变（所有装饰在这一步之前已全部应用完毕，描边早已统一为单条）。
- hover 缩放比例 1.015 → **1.012**：缩放比例直接决定重采样像素量与外扩重绘面积，仍读得出「卡片浮起来」，快速掠过多张卡片时更轻。
