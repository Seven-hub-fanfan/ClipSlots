## ClipSlots v2.11.8（画布：文字随卡片等比缩放，不再溢出/抖动）

> 本 tag 已第三次重打包：指向十轮修复的 commit，替换了九轮的 `dafafd2`。
> 前几轮（二~九轮）走的是「屏幕字号恒定 + 反向补偿」路线，本轮按用户录屏结论**整条推翻**。

### 1. 根因：不是系数不准，是量纲混了

九轮把补偿系数算到了像素级精确（离屏测量四档 0px 误差），但用户录屏里的现象是
**文字从卡片底部溢出、悬浮在画布背景上**，并伴随换行抖动。原因在这两行：

```
卡片排版宽度 = 260 × zoom      ← 随缩放变
文字排版字号 = 13（屏幕固定）  ← 不随缩放变
```

缩到 25% 时容器只有 65pt 宽，却要塞按 13pt 排版的字 —— 文字相对容器胀成 4 倍，
SwiftUI 只能多折行（而且容器宽度每帧在变 → 每帧重新折行 = 抖动），补偿层再把这坨
已经折错的文字整体放大 4 倍 → 越过卡片边框。**系数再准也修不了「内容比容器大」。**

### 2. 十轮架构：布局与缩放彻底分离

```
卡片内部：全部按设计稿 pt 排版（260pt 宽、13pt 字、12pt 内边距……），与 zoom 完全无关
节点层：  唯一一层 scaleEffect(zoom, anchor: .topLeading)
```

- 视觉字号 = 设计字号 × zoom：文字与卡片属于**同一个相似变换**，从结构上不可能溢出边框；
- zoom 不进入任何 `frame` / `font` / `padding` → SwiftUI 没有任何理由重新折行 →
  **换行位置在 25% 与 200% 下逐字相同**，缩放全程无跳变；
- zoom 唯一被允许穿进卡片的形式是量化后的 `gateZoom`，且只参与「写不写字」的布尔判定：
  节点屏幕视觉短边 < 40pt 时**整块文字**淡出（牌面卡阈值 24pt），不做逐行隐藏；
- 代价是放大后文字是位图变换、略软 —— 这是本轮**刻意**接受的取舍。

### 3. 删除的旧零件

- `CanvasScreenText.swift`（屏幕固定字号排版 + 逐行/逐块可见性）→ 由 `CanvasNodeText.swift` 取代（只剩行高度量 + 可见性闸门）；
- `CanvasZoomLayout.swift`（排版档位阶梯 + 迟滞 + 落定延时）整体删除；
- `CanvasTextStability.swift` 里的 `canvasScreenFixedText`（文字反向补偿 modifier）删除，
  只留 `canvasStableText` / `canvasStableLabel`（禁止字距收紧与字号自适应，与缩放架构无关）；
- 视图层 `renderScale` / `textCounter` 入参全部删除；`CanvasWorkspaceView` 的 `layoutZoom`
  state、`settleLayoutZoom` / `scheduleLayoutZoomSettle` 落定防抖一并删除；
- `CanvasCardLayout.verticalPlan` / `textNodePlan` 去掉 `renderScale` 参数，改为纯设计单位。

文本节点的纵向预算（保输入框 → 先砍「入参文件」行 → 再不够整体不写字）与
「只留扇形展开、右键无『展开样式』子菜单」都保持九轮结论不变。

- `swift build` 通过；零依赖 smoke：**通过 17667，失败 0**
  （新增三组：布局与 zoom 解耦、文字等比缩放 + 换行恒定的 25%→200% 逐 1% 扫描、40pt 文字闸门）。
